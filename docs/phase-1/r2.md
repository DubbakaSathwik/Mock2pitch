# Cloudflare R2 reference

## Buckets and credentials
One **private** bucket per environment (names supplied by the user). No public bucket access, no `r2.dev` URL, no custom public domain. Supabase Storage is not used. Credentials (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`) exist only as **Edge Function secrets**; they never reach the browser or Next.js client bundle.

## Object keys (server-built from DB-verified UUIDs — the client never supplies a key)
```
users/{user_id}/decks/{deck_id}/source.pdf
users/{user_id}/decks/{deck_id}/slides/{slide_index}.jpg
users/{user_id}/sessions/{session_id}/audio/{slide_index}.wav
```
`keys.*` in `_shared/r2.ts` rejects anything that is not a UUID or a 0–9 index. Original filenames live in Postgres only (path and control characters stripped, ≤ 200 chars). `files.object_key` is not selectable by clients.

## Presigning (SigV4 query auth, `aws4fetch`, region `auto`)
| Object | Method | Expiry | Signed headers |
|---|---|---|---|
| PDF | PUT | 5 min | `content-type: application/pdf`, `content-length` = declared size |
| slide JPEG | PUT | 5 min | `content-type: image/jpeg` only (size unknown until the page is rendered) |
| audio WAV | PUT | 10 min | `content-type: audio/wav`, `content-length` = declared size |
| any download | GET | 10 min | – |

The API returns `upload.headers`; the browser sends `Content-Type` (it cannot set `Content-Length`; the browser computes it from the body, which must equal the declared size). Presigned URLs are bearer credentials — never log them.

**Independently verified:** `tests/r2/r2.test.ts` runs the signer against a fake S3 server that re-derives the SigV4 signature from the received request and checks that a different `Content-Type`, a different body length, a changed key, a changed `X-Amz-Expires`, and a request after expiry are all rejected, and that unsigned access is denied.
**Not verified against real R2** (no bucket/token): that R2 itself enforces the signed `Content-Length`, and CORS preflight behaviour. Because of that, size is **also** checked server-side after upload (HEAD size must equal the declared size / be ≤ limit) and oversize objects are deleted.

## CORS
`infra/r2-cors.json` (no wildcard origin; edit the Netlify origin first):
```bash
npx wrangler r2 bucket cors set <bucket> --file infra/r2-cors.json
```
Netlify deploy-preview origins are **not** listed; add specific preview URLs when testing previews or accept that browser uploads from previews fail. CORS is not authorisation: every URL is issued only after Supabase auth and ownership checks.

## Lifecycle
| Object | Kept until |
|---|---|
| `source.pdf` | account deletion; deleted immediately when validation fails |
| `slides/*.jpg` | account deletion |
| `audio/*.wav` | report generated (deleted then); retry window ≤ 24 h; swept at 24 h regardless |

**Limitation / open question:** the prompt asks for an R2 lifecycle safety-net on `users/*/sessions/`. R2 lifecycle rules match a literal **prefix** (no wildcard), so with this key layout the only possible rule would cover all of `users/` and would delete PDFs/images. No such rule is configured. The sweeper is the sole 24 h mechanism. Proposed fix if the owner wants the safety net: store audio under a top-level prefix (e.g. `audio/users/{user}/…`) so `prefix=audio/` + age 1 day is expressible; `keys.audioClip` and account deletion (a second prefix) are the only code to change.

## Flows
- **Upload**: `deck-upload-init` → PUT → `deck-upload-complete` (HEAD size, `%PDF-` signature, `pdf-lib` page count, not encrypted) → PUT images → `deck-process` (HEAD size ≤ `SLIDE_IMAGE_MAX_BYTES`, `FF D8 FF` signature).
- **Download**: `asset-urls` (owner only; keys read from the DB).
- **Delete**: failed validation → object deleted at once; audio → after the report (row marked `deleted` only after R2 confirms); account → `deletePrefix('users/{uid}/')` with pagination, recorded in `private.pending_deletions` first so the sweeper can finish it.
- **Orphans**: the sweeper fails `pending` files after 1 h (deleting the object), reopens sessions stuck in `uploading_audio`, and deletes audio older than 24 h. Tested in `tests/functions/admin-account-sweep.test.ts`.

## Known limitations
Presigned PUT cannot cap slide-image size (see above); R2 behaviour for signed `Content-Length` unverified; no virus scanning (type, size, signature and page count only); a deleted object that R2 later fails to confirm stays `uploaded` until the next sweep.
